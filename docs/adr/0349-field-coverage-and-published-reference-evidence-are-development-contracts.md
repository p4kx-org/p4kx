# Field coverage and published reference evidence are development contracts

Use a development-only owner/field inventory to distinguish source declarations, observed
population, typed projection and mapper rejection; generic readability alone cannot establish
retention. Keep published scunpacked evidence separate from controlled producer-run manifests
because its generator revision and source DCB identity are not established. Permit numerical
assertions only when a source-reviewed publication's exact Channel, public game-version and
change number match the observed Archive, preserving unavailable provenance explicitly.

## Consequences

Domain tickets contribute exact field mappings incrementally. Unreviewed declarations, declared
target drift and newly populated families remain visible independently of current concrete
mapper support. Primitive arrays and GUID multimaps preserve individual values and one-to-many
relationships; both-missing and derived-only results never manufacture comparison evidence.

Shared bounded offline primitives belong in testkit. The controlled reference harness delegates
containment and alias checks to them, while its manifest parser remains independent. Local file
hashes identify supplied bytes without attesting their publication origin or foreign execution.

Runtime catalog serialization and shipped network behavior are unchanged. Synthetic tests cover
the verification contract; real runs use private opt-in data and publish aggregate counts only.
[The guide](../catalog-field-verification.md) owns setup, bounds and detailed evidence rules.
