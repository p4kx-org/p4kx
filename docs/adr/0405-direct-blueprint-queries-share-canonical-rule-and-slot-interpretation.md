# Direct Blueprint queries share canonical rule and slot interpretation

The selective SDK supplies complete physical Blueprint definitions, tier configurations and
canonical presentation without executing the whole crafting reader or constructing a Catalog.
It reuses blueprint_catalog_read and the canonical row/table finalizer. Definitions and original
source arenas move into the callback result; they are not serialized, reconstructed or cloned.
The same immutable nested types expose every original slot, modifier, range and research field.

Selection uses the existing Blueprint admission and leftover policy for All, GUID and RecordIndex.
Equal GUIDs retain every eligible physical owner in textual GUID and physical-index order. Each
tier and arena reference stays associated with that exact owner. Formula version1 quality identity
is unchanged: Build, selected physical Blueprint, original tierIndex and the mandatory/optional/
option parent route. Debug names and arena-local valueIndex references are not exchange keys.

Default availability and item exclusions depend on the original CraftingGlobalParams family.
The canonical dismantle-choice interpreter requests its process input only after its existing
missing-item and positive-blacklist returns. The producer provides its prepared borrowed process
sources. The SDK prepares and caches that same needed family at the first actual request, including
original leftover selectors and failed-source knowledge. It selects a process only when exactly
one live physical candidate has the canonical dismantle type; equal-GUID candidates still count
separately. No process-body read is needed for a missing or positively blacklisted item.

Category finalization keeps the existing canonical failed/skipped physical-candidate policy.
Only category GUIDs actually authored by selected owners require candidate bodies. A matching-GUID
candidate with an unclassifiable original path or type retains the authored category GUID and makes
that derived choice's source set incomplete, including when known failed or skipped aliases exist.
The shared finalizer uses original captured header receipts and retains their attempted inputs; a
requested GUID alone does not prove a Category source identity. A readable path or type proving a
candidate foreign does not affect category knowledge. Unclassifiable possible candidates remain
explicit dependency coverage gaps. Other Resource, Item, GameplayProperty and quality references retain their
original header/arena links without opening their bodies. No reward, mission, world or placement
body census is involved.

Owner coverage and separate global/process/category coverage remain visible. A successful callback
and outer Result are not completeness certificates. Consumers inspect both coverage and each
source cell before publishing owned cache changes after outer success. Returned texts and all
source-use references resolve through that result's own registry and source inventory. Cancellation
and Archive-change checks remain those of the reusable query session.

These additive Rust APIs preserve existing Schema v3 fields, source axes and quality formulas.
They cover definitions.blueprints, configurations.blueprintTiers and
projections.blueprintPresentation, not the independent global, dismantle, reward or quality
families. The entire selected family can be requested, or one physical owner without that work.
