# Canonical mining and refining tables preserve original owner data

MiningGlobalParams and RefiningProcess use the canonical routes selected by the v3 data-family
map: configurations.miningGlobal and definitions.refiningProcesses. These typed tables replace
the two legacy root arrays. Schema version remains the unpublished v3, with no parallel legacy
payload. The released v2 schema fixture stays immutable and supplies exhaustive old-field migration
dispositions, including the protected refining name's key/en/de leaves.

Each row has the independently sourced physical Record header, a complete owner-local original
field arena and direct sourced projections. Mining retains all 37 exact numeric fields and the
states of their three owned blocks, plus the original waste-resource reference header. Refining
retains the protected original Locale reference and open String/Enum labels. Unknown original
members remain traversable; a readable source representation is not converted into an invented
semantic value. Original units, integer widths, IEEE bits, signed zero, null and missing states
stay intact. No concrete class name, unit conversion or yield formula is inferred from labels.

The canonical reader shares PreparedDefinition, Observed and the original physical Record scope.
The full arena and typed projections read the same original facts. Identical nonfinite receipts
for two views of one occurrence merge by physical occurrence; contradictory receipts fail.
Numeric coverage remains bound to rows actually emitted. Lossless original retention satisfies
raw-value evidence but never grants complete health to a failed required typed projection.

The direct SDK queries reuse these canonical readers and the existing selective mining planner.
A narrow catalog_queries::mining module exposes complete borrowed immutable rows, text and source
inventories. All/GUID/RecordIndex preserve every admitted physical alias with canonical ordering.
Only selected owner bodies and demanded requested locales are read. References consult headers;
Resources, reverse groups, world placements and a complete Catalog are not dependencies. No fixed
materialization quota is added.

Availability, physical owner failures, typed field failures and demanded dependency coverage
remain separate. Consumers retain ownership of cache publication and commit updates only after
outer success and the required coverage checks. The query session preserves Archive binding,
change detection and cancellation. Exhaustive typed getter-versus-wire/source-inventory checks,
actual body-read observers and normal-publication counterfixtures verify these boundaries.
